# 07 — Уведомления из HA

## Цель

Бот сам присылает сообщение при событиях HA: дверь открыта, датчик движения, сработала сигнализация.

## Контекст

MCP-notifications от HA пока не поддерживаются (HA MCP Server не отправляет notifications через MCP). Поэтому для уведомлений используем REST API HA (опрос состояний с кэшем) или WebSocket (подписка на state_changed).

Проще: периодический опрос `ListEntities()` через MCP (сравнение с кэшем) + WebSocket для реального времени. Реализуем через REST API напрямую для надёжности.

## Что сделать (чек-лист)

- [ ] `internal/notify/engine.go`:
  - подписывается на WS-канал событий HA (через `gorilla/websocket`: `ws://HA_URL/api/websocket`)
  - авторизация по long-lived access token
  - подписка на `state_changed` события
  - reconnect с exponential backoff
- [ ] конфигурация уведомлений:
  - в `config.yaml` секция `notify` со списком `entity_id` для отслеживания
  - wildcard: `binary_sensor.*` для целого домена
  - дефолт: все `binary_sensor.*` и `sensor.*` с категорией safety/security
- [ ] формат сообщения: лаконично
  - `Дверь входная — открыта`
  - `Температура в спальне: 23.5°C`
- [ ] дебаунс: не чаще 1 раза в N секунд по одному entity (N конфигурируемое)
- [ ] опция «пауза уведомлений на N минут/часов» (команда `/quiet 1h`)
- [ ] интеграция с core: отправка через TG-канал бота
- [ ] старт/стоп уведомлений при старте/стопе бота

## Зависимости

- этап 04 (tg — отправка сообщений)
- библиотека: `gorilla/websocket` или `nhooyr.io/websocket`

## Проверка

Открыть дверь — приходит сообщение в Telegram. `/quiet 1h` — уведомления замолкают на час.
